**这个仓库是什么、基于什么**：本仓库是 **NeoForge 26.2** 的 fork（上游：<https://github.com/neoforged/NeoForge>），
在它之上加了一层 **NeoFobric 桥**：把**真正的 fabric-loader + Fabric API** 带进 NeoForge 的进程里，
让两个加载器的模组并排运行。桥本身的代码在 `projects/fabricbridge/`（另有少量平台侧补丁与钩子）。

下面按"**谁的部分按谁的协议**"讲清楚。**不要把本仓库理解成单一协议覆盖一切** —— 它是若干部件放在一起。

### 关于 LGPL 的"传染性"

LGPL v2.1 是特意选的：**别的项目可以链接、依赖本项目的 API，而不必自己也用同一协议**。
也就是说：**用这个加载器去跑你的模组，不会要求你的模组改用 LGPL**。

## 四、要不要改成"混合协议"？

**不需要，也不建议**把整个仓库标成 "mixed license"：那样反而说不清哪块归哪条协议。我们的做法是：

1. **按部件声明**（见上表）：LGPL-2.1-only 覆盖 NeoForge 与桥；第三方部件保留各自协议；
2. 发布安装器时**把各方的许可文本一并带上** —— 构建已经保留了嵌套 jar 的 `META-INF`（内含各自的
   `LICENSE`/`NOTICE`），发布时另附本文件、`LICENSE.txt`，以及 Fabric API 与 fabric-loader 的
   Apache-2.0 文本即可；
3. 不要声称 LGPL 覆盖第三方部件，也不要声称第三方协议覆盖 NeoForge/桥。
